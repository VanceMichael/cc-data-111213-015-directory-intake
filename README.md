# 共享目录变动中的稳定文件资料

directory-intake 用于合作资料的本地查看和来源保存。当前版本支持人工触发的整份资料查看与字节级归档，以及面向仪器共享目录的持续采集：采集器只在文件内容稳定后领取，资料对象按内容摘要保存，每次领取保留单独回执。自动组织领域资料的能力与人工查看入口分别演进。

## 运行环境

使用 Node.js 22。依赖已锁定；首次准备执行 `npm ci --ignore-scripts`，正式运行无需下载资料或软件。全部样例使用合成数据与本机来源，不连接生产系统。

```bash
npm run check
npm test
npm run demo
npm run demo:collector
```

`npm run demo` 在临时目录实际读取资料、归档并重新核验摘要，退出时清理临时内容。`npm run demo:collector` 用本地写入器主动制造通知缺失、路径复用、复制中变更、硬链接归档、链接逃逸和长时间不停写，演示持续采集的行为边界，正常在两分钟内结束。

## 资料操作

```bash
npm start -- inspect fixtures/instrument/measurement.csv
npm start -- capture fixtures/instrument/measurement.csv .local/archive
npm start -- list .local/archive
```

`capture` 只表示来源字节已保存，不声称领域流程已自动完成。已有查看功能只展示现有资料，不替代业务接纳判断。`scripts/create-fixtures.js` 用于维护者重建合成资料；运行与测试直接读取已提交的资料。

## 持续采集

```bash
npm start -- collect <观测目录> <归档目录> [--state 台账路径] [--once] [--no-watch] \
  [--quiet-ms 1000] [--scan-ms 5000] [--max-wait-ms 60000]
```

采集器持续观测仪器写入的共享目录，把每份稳定内容领取进归档。`--once` 跑到没有待定条目为止（有界）后打印台账；默认持续运行，Ctrl-C 打印台账后退出。

### 目录通知只是提示

目录通知（`fs.watch`）可以重复、丢失或整段缺席，因此通知只用于降低延迟：通知去抖后触发一次目录重扫，真正的依据始终是重扫本身。周期重扫（`--scan-ms`）兜底；有待定条目时还会按静默期自动补扫。通知完全缺失（`--no-watch`）时行为不变，只是更慢。

### 资料状态

每份被跟踪的内容处于以下状态之一，台账（`collector-state.json`，原子写）持久保存，重启后续用：

- **观察到 observed**：看到某个路径上的某份内容签名（设备、inode、大小、mtime/ctime 纳秒），等待静默。
- **稳定候选 stable**：签名在静默期（`--quiet-ms`）内没有变化，可以尝试领取。
- **已领取 claimed**：内容已通过复制期校验并写入归档，回执与内容摘要记录在案。
- **待人工检查 review**：出现需要人工判断的情况（见下）。非粘性条目在内容变化或稳定后会自动回到观察流程，不丢资料；粘性条目不再自动领取，等待人工。

路径不是文件身份：同一路径改名覆盖（新 inode）或截断重写（同 inode 新内容）都视为新内容，重新进入观察周期。inode 也可能被回收，因此领取去重的最终依据是内容摘要，inode 只用于观察期签名。

### 领取与复制期防护

领取一份稳定候选时：

1. 以 `O_NOFOLLOW` 只读打开，比对打开前后 (dev, inode)，并经 `/proc/self/fd` 解析句柄真实路径，确认仍在授权根目录内——符号链接一律不跟随，中间目录被改名或替换成符号链接也不能把读取引到根目录之外。
2. 复制前后各取一次元数据，并做第二遍摘要复核。源文件在复制期间变化（大小、mtime/ctime 变化，或两遍内容不一致）就**撤销本次领取**，绝不把前半旧内容和后半新内容拼在一起；读取以复制前的大小为界，不追赶持续增长的文件。
3. 撤销后回到观察状态重试；反复撤销达到上限转为粘性待人工检查。

每份内容（按摘要）只领取一次。硬链接或内容相同的另一路径只把来源路径并入已有领取记录，不产生第二份回执。回执是"哪些内容被领取过"的最终依据：进程在写台账前崩溃，重启后也会从回执重建去重集合，不会重复领取。

### 长时间不停写的文件

始终无法静默满一个静默期的文件，超过 `--max-wait-ms` 后进入待人工检查（非粘性）。采集器继续观察：内容再变化会重新计时，停笔稳定后仍会被领取，但人工检查标记保留在台账与回执元数据中。反复超时超过上限（默认 4 次）后转为粘性，不再自动领取——这通常意味着仪器行为异常，需要人工介入。

### 明确不承诺的事

- 不承诺对任意写入方式获得原子快照。承诺的是：变化必被发现、发现必撤销、撤销必重试，领取的内容一定对应源文件某一连续稳定时期的完整字节。
- 不删除、不改写仪器目录中的任何内容；归档目录与台账必须位于受观测目录之外，启动时强制检查。
- 内容相同的文件按一份内容领取（内容寻址），需要按路径区分资料的业务应看回执中的来源列表。

## 目录约定

- `src/domain.js`：现有领域读取和查看接口。
- `src/archive.js`：内容对象、来源回执与完整性检查。
- `src/collector.js`：持续采集：重扫、稳定性判定、复制期校验、台账与状态机。
- `fixtures/`：本地资料与领域配置。
- `test/`：已有行为的运行验证，使用独立临时目录。
- `scripts/demo-collector.js`：对抗性本地写入器演示。

## Linux 环境

`Dockerfile` 使用 Node.js 22 镜像；浏览器项目使用包含 Chromium 的运行镜像。可执行 `docker build -t directory-intake:local .` 后运行 `docker run --rm --network none directory-intake:local npm test`。测试中的 HTTP、MQTT 和门户都仅绑定回环地址；不需要第二个容器。构建阶段准备依赖，运行时不安装依赖。持续采集依赖 Linux 的 `/proc/self/fd` 做打开句柄位置核验，并使用递归目录通知（通知不可用时自动退化为周期重扫）。
